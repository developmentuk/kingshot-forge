# Sprint 8.2 — Hero Domain Completion

## Release

Release 0.6.0 — Hero Domain Complete

## Objective

Complete the public Hero Domain using the existing editorial platform and published canonical projections. No new publishing architecture or parallel content source is introduced.

## Delivered public experience

The Hero Companion now brings the published Hero catalogue and published Hero Skills together into one responsive guide experience:

- hero synergies derived from published catalogue relationships;
- recommended formation role and troop focus;
- strengths and weaknesses grounded in published ratings, availability and tags;
- best-use editorial guidance;
- staged Hero progression recommendations;
- explicit Widget progression guidance;
- explicit Exclusive Gear guidance;
- published Hero Skills rendering with published-only empty states;
- provenance, confidence and source details;
- responsive jump navigation and touch-sized mobile controls;
- loading, unavailable, not-found and no-results states;
- issue reporting from the Hero detail surface.

## Published-data boundary

The public experience consumes:

- active Hero records from the existing published Hero catalogue projection;
- active Hero Skill records from `public.published_hero_skills`.

Recommendations are deterministic presentation guidance derived from published fields. The implementation does not create editable duplicate records and does not read editorial drafts.

The progression guide intentionally avoids unpublished numeric costs, material requirements or breakpoints. It explains investment order using published role ratings, availability and long-term classification only.
