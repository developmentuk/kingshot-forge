# Version 1.1.0 — Entity Identity Foundation

## Status

Implementation checkpoint on `feature/1.1.0-stable-entity-identity`. The shared
Forge ID contract, server-authoritative type registry, fail-closed resolver,
legacy translation contract and additive Search field are implemented. The
Supabase migration is review-gated and has not been applied; no production
data, Buildings publication record, Hero record or publication version was
mutated.

## Contract

Forge IDs use `namespace.local-key`. Components are lowercase ASCII words with
hyphens. Nested local keys are permitted for explicitly nested domains, for
example `hero-skill.amadeus.royal-command`. Invalid IDs fail closed.

## Persistence and security

Identities are hybrid: the type registry is persisted centrally; entity IDs are
derived from canonical records until central persistence is approved. The
proposed registry table has forced RLS, safe enabled-metadata reads, and
service-role-only writes. No `forge_entities` table or bulk identity backfill
is included.

## Known limitations

Only Buildings and Heroes have implementation adapters in this checkpoint.
Nested Hero Skill, media, tags and authored relationship CMS work remain
deferred. Supabase CLI is unavailable in the workspace, so migration creation
and live verification require the supported CI/owner environment.
