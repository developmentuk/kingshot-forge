## Scope delivered

Phase 1 adds the repository foundation needed for a later controlled Oasis publication: a versioned public projection, forward-only migration proposal, deterministic WebP projection and private manifest, a fail-closed published-only loader, an inactive Search adapter, and a development-only UI acceptance entry point. It does not register a public dataset, API, route, navigation item or Search provider. Derivative media remains private and unstaged for production publication.

The public record allow-list is: `schemaVersion`, `id`, `name`, `aliases`, `recordType`, `rarity`, `availabilityCategory`, `footprint`, `typeLimit`, `maxLevel`, `function`, `levels`, `maxEffects`, `unlock`, `upgrade`, `maxProsperity`, `trustLabel`, `media`, `publicationId`, `publicationVersion`, `publishedAt`, `updatedAt`, `canonicalRoute`, and `status`.

The projection rejects or drops `_meta`, source documents and table indexes, source URLs and raw source objects, `sourceText`, verification history and notes, provenance and research conflicts, original filenames, private inventories, repository/filesystem paths, and all other non-allow-listed fields. Null and absent values remain unknown; the builder does not infer game values. Public projection schema v2 maps each recognised private verification status to an explicit public trust label and rejects missing or unsupported states. `Owner verified in-game` is reserved exclusively for the explicit `owner_direct_ingame_verified` source status; it is not assigned to the current catalogue wholesale.

The runtime boundary now enforces that allow-list as an exact required shape and recursively validates every public value before publication, loading or Search projection. Aliases are unique non-empty trimmed strings. Footprint, unlock and upgrade objects require their exact keys. Every level and bonus/maximum-effect entry is a non-null exact-shape object; level identifiers are positive integers when known, numeric measurements are finite and non-negative where applicable, nullable strings follow the trimmed-string policy, known effects are strings, and exact-output state is boolean or null. Public media retains exact key, WebP-path, role, level-variant, dimension and manifest matching. A separate strict staged-source validator runs before source fingerprinting, projection and media/fixture generation. It validates every consumed identity, catalogue, level, bonus, effect, unlock/upgrade, verification and image-mapping value without trimming, coercing, filtering or silently substituting malformed input; every valid level and bonus is projected exactly once.

## Publication proposal

`20260816150042_oasis_001a_pub_phase_1_foundation.sql` was created with Supabase CLI 2.114.0. It proposes immutable version and record history, a separate atomic current pointer, manifest identity, exact record/media counts, actor/reason/time evidence, unique idempotency keys, transaction advisory locking, append-only audits, service-role-only execution, RLS/revokes, publication-tied Search refresh state, and rollback by creating a new publication. Before activation it validates the complete manifest and record payload, recursively rejects forbidden keys, checks exact record/media/publication identity, and recomputes manifest and record-content SHA-256 values from a deterministic SQL canonical-JSON contract shared with TypeScript. Record-content identity sorts by stable record ID and excludes only `publicationId`, `publicationVersion`, `publishedAt`, and `updatedAt`; the immutable version and audit evidence store that hash. An idempotency retry must match publication identity, manifest hash, source fingerprint, record-content hash and rollback source before history or the current pointer can change.

The RPC boundary accepts explicit pre-publication candidate records, not stored-record identities. Candidates bind `publicationId` and must leave `publicationVersion`, `publishedAt` and `updatedAt` as JSON null. `publication_version` is `GENERATED ALWAYS AS IDENTITY`; after inserting the immutable version row, the RPC uses its returned version and the single captured authoritative timestamp to stamp every stored record. PostgreSQL sequences guarantee uniqueness rather than consecutiveness, so rolled-back allocations may leave gaps and no caller value is predicted or compared. Idempotent retries return the existing stored version without allocating another version or rewriting history. Rollback-derived candidates use the same null placeholders before the database stamps a new forward-only identity. Runtime sequence-gap and concurrent-caller execution remains a mandatory Phase 2A PostgreSQL gate; Phase 1 verifies this ordering and ownership structurally only.

The shared canonical-number contract is `oasis-canonical-json-v1`: finite values only, absolute magnitude at most 100,000,000, and at most seven decimal places. Canonical text never uses exponent notation, converts negative zero to `0`, and removes redundant zeros; stored public records retain numbers rather than hash strings. The record-content algorithm is domain-separated as `oasis-record-content-sha256-v2`. Its governed fixture hash changed from `d1d94f55cdefa25273f1292b3c03afe9156d620e2b60b690211a32fe1e76117b` to `a4b8634f4a4004d75c7102273a1e7b9c500967b1d781ba0257b4646618cb7da2`; the manifest hash and WebP binaries did not change. Fixed vectors cover zero/negative zero, signed integers, decimals/redundant zeros, ±`1e-7`, JavaScript exponent-format boundaries, maximum magnitude/precision, rejection, nesting, key/record ordering, canonical text and record hash. The TypeScript vectors execute in Phase 1 and the SQL migration embeds the matching values and expected hash, but actual PostgreSQL parity execution remains a Phase 2A gate.

After complete payload validation, the RPC acquires the publication advisory lock and captures one millisecond-precision `clock_timestamp()` value. While holding the lock, it compares that value with the current publication timestamp and advances it by one millisecond when necessary, so serial publications remain strictly monotonic even when the wall clock resolves to the same millisecond. That one captured value is written to the immutable version, every stored public record, rollback-derived records, the Search-refresh request, audit event and current pointer. Idempotent retries return the existing publication identity without rewriting its timestamp or history. Caller timestamps are never persisted; rollback receives a new forward-publication timestamp. Search preparation also rejects records whose timestamps differ from the database publication row. Rollback locks publication state, requires an Oasis-owned complete immutable target, verifies the stored manifest and record-content hashes, binds source fingerprint, manifest and content to that source, and derives the new forward-only snapshot from history before any write. The ineffective `current_user` test remains removed: explicit `EXECUTE` revokes and the sole `service_role` grant are the documented caller boundary for the `SECURITY DEFINER` RPC. The migration was not applied to local or remote Supabase.

It imports all 111 private derivatives and the placeholder through a development-only `import.meta.glob` edge, preserving catalogue/detail review, text and rarity filtering, all level tables, WebP artwork and placeholder states, responsive desktop/mobile CSS, and links to the existing Island Chest Route Optimizer. It is not imported by `src/main.tsx`, and the production app has no Oasis route. A clean production Vite build is asserted to contain no Oasis derivative checksum, placeholder, acceptance fixture identity, acceptance HTML/entry, old Island Route PNG or scenic draft.

The Search adapter prepares published records with dataset `oasis-island`, stable IDs, canonical building routes, sanitised text/media, publication identity and published status. Before mapping any Search output it validates every record and authoritative timestamp, recomputes the governed record-content hash over the complete set, and fails closed on malformed or stale identity. The published-only loader independently verifies that hash and recursively freezes its returned records and all nested arrays/objects as defence in depth. Oasis remains absent from `PUBLISHED_DATASET_KEYS` and the live Search runtime registry. Tests reject source-staged, unpublished, forbidden-field and valid-shaped integrity mutations.

## Risks and Phase 2 blockers

- The migration requires owner review, controlled application and database-level acceptance before any publication can exist.
- The adversarial SQL suite must be executed in an approved disposable Supabase/PostgreSQL environment before migration approval; local structural checks are not database execution.
- Concurrent publication ordering and same-millisecond monotonicity require actual PostgreSQL execution in Phase 2A; Phase 1 proves the ordering structurally but does not claim runtime concurrency acceptance.
- The first publication needs an authorized actor/reason/idempotency key and a verified manifest/record payload.
- Public API/Data Engine registration, Search refresh activation and public routes/navigation remain deliberately absent.
- Desktop and approximately 390px mobile visual acceptance must be repeated against the final published-only runtime, including transparent WebP quality and the optimized header.
- The scenic draft requires an explicit later archive/removal decision if it should leave the repository.
