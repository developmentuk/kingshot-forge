# Release 0.7.2 — Player-facing activation

## Player Identity

- Completed the private Player Identity loading, signed-out, unlinked, linked and Supabase failure states.
- Kept `PlayerIdentityContext` as the single browser source of truth for the primary linked player.
- Consolidated linked-player reads and refreshes around the context and retained the `kingshot-player-updated` event.
- Removed the synthetic public identity route and routed both public URL forms through the real public profile projection.

## My Forge

- Added a responsive Player Headquarters with real player name, kingdom, optional alliance, verification, visibility and avatar fallback.
- Added state-driven priority actions for signing in, linking, profile completion, visibility and Hero Showcase maintenance.
- Removed the duplicate Forge Passport summary while preserving linked-player management and saved name/art functionality.

## Security and validation

- Public profile reads no longer select `user_id` and require both account and profile visibility.
- No Supabase schema change was required.
- `npm run validate:player-identity`, `npm run test:player-identity`, `npm run build` and `npm run lint` pass; lint retains existing warnings documented in `docs/AEGIS.md`.

## Player Planning

- Completed `/my-forge/progression` as a linked-player-owned progression snapshot editor with loading, unlinked, empty, partial, save-success and save-error states.
- My Forge planning progress now reads the primary account from `PlayerIdentityContext` and calculates completion from six explainable saved sections rather than synthetic weights.
- Priority actions link only to registered routes: player identity, profile, progression, Hero Showcase and Transfer Profile.
- Transfer completion counts only a non-draft owned transfer profile; public visibility remains separately represented and private contact fields remain outside public projections.
- Profile, progression, Hero Showcase and Transfer updates refresh the planning panel through the existing `kingshot-player-updated` event.
- Added `.env.example` with publishable Supabase placeholders and documented the minimum local setup.

## Player Planning correction

- Restored `/my-forge/transfer-profile` as the canonical private editor path while retaining `/transfer-profile` for existing public links; both use the existing Transfer Profile component.
- Town Center is now read-only API-owned context from `PlayerIdentityContext`. The existing snapshot column is populated from that linked-player value for historical display and cannot be edited by the player.
- Personal progression uses the published Data Engine dataset route. Infantry, Lancer and Marksman options come from normalised `troops` records; Truegold options come from published `truegold_tg1`–`truegold_tg8` fields; VIP options come from published VIP level records. The service revalidates those supported values before saving.
- Governor Gear and Governor Charm remain controlled numeric score fields: their published datasets describe per-step/per-level progression rather than a reliable whole-governor score. Non-negative validation prevents invalid new scores while preserving legacy history.
- Legacy saved values remain visible. Values outside the current published options are shown as `legacy — review` options and are rejected if submitted unchanged, so a player can replace them safely without migration.

Known limitation: authenticated Supabase RLS and direct browser smoke checks require Clark's local signed-in session or a deployed preview; this session did not claim visual browser validation.
