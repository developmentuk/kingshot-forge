# Release 0.7.2 — Player-facing activation

## Player Identity

- Completed the private Player Identity loading, signed-out, unlinked, linked and Supabase failure states.
- Kept `PlayerIdentityContext` as the single browser source of truth for the primary linked player.
- Consolidated linked-player reads and refreshes around the context and retained the `kingshot-player-updated` event.
- Removed the synthetic public identity route and routed both public URL forms through the real public profile projection.

## My Forge

- Added a responsive Player Headquarters with real player name, kingdom, optional alliance, verification, visibility and avatar fallback.
- Added state-driven priority actions for signing in, linking, profile completion, visibility and Hero Showcase maintenance.
- Removed the duplicate Forge Passport summary while preserving linked-player management and saved name/art functionality.

## Security and validation

- Public profile reads no longer select `user_id` and require both account and profile visibility.
- No Supabase schema change was required.
- `npm run validate:player-identity`, `npm run test:player-identity`, `npm run build` and `npm run lint` pass; lint retains existing warnings documented in `docs/AEGIS.md`.

## Player Planning

- Completed `/my-forge/progression` as a linked-player-owned progression snapshot editor with loading, unlinked, empty, partial, save-success and save-error states.
- My Forge planning progress now reads the primary account from `PlayerIdentityContext` and calculates completion from six explainable saved sections rather than synthetic weights.
- Priority actions link only to registered routes: player identity, profile, progression, Hero Showcase and Transfer Profile.
- Transfer completion counts only a non-draft owned transfer profile; public visibility remains separately represented and private contact fields remain outside public projections.
- Profile, progression, Hero Showcase and Transfer updates refresh the planning panel through the existing `kingshot-player-updated` event.
- Added `.env.example` with publishable Supabase placeholders and documented the minimum local setup.

## Player Planning correction

- Restored `/my-forge/transfer-profile` as the canonical private editor path while retaining `/transfer-profile` for existing public links; both use the existing Transfer Profile component.
- Town Center is now read-only API-owned context from `PlayerIdentityContext`. The existing snapshot column is populated from that linked-player value for historical display and cannot be edited by the player.
- Personal Progression is present in the My Forge desktop and mobile navigation. The published Data Engine supplies Infantry, Cavalry and Archers options; source `lancer` and `marksman` identifiers remain internal compatibility keys and are mapped to Cavalry and Archers in the UI. Truegold options come from published `truegold_tg1`–`truegold_tg8` fields and VIP options come from published VIP level records. The service revalidates supported values before saving.
- Governor Gear and Governor Charm remain controlled numeric score fields: their published datasets describe per-step/per-level progression rather than a reliable whole-governor score. Non-negative validation prevents invalid new scores while preserving legacy history.
- Legacy saved values remain visible. Values outside the current published options are shown as `legacy — review` options and are rejected if submitted unchanged, so a player can replace them safely without migration.
- Forge completion now uses four equal required milestones: linked identity, player profile, first progression snapshot and six-slot Hero Showcase. Transfer Profile is optional and appears as the presentation-only Transfer Ready badge when voluntarily completed; Public Presence is also an optional badge. Neither changes the required percentage or next-action sequence.
- My Forge progress is presented as a status summary, one next action, core milestone links and earned/locked presentation badges. The badges derive from existing player/profile/progression/showcase/transfer reads and do not create new persistence.

## Player Passport consolidation

- `/my-forge/player-identity` remains the compatible route but is now visibly named Player Passport and is the full private account home.
- My Forge is a lightweight landing page with a compact Passport/progress summary, tool shortcuts, a small earned-badge preview and local Forge Library counts. The full milestone and badge presentation lives on Player Passport.
- `/my-forge/profile` is visibly Edit Passport. Its linked-player context is compact and read-only; editable fields are limited to profile presentation and visibility controls.
- Personal Progression remains separate and focused on historical snapshots. Transfer Profile remains available as an optional tool and never affects required completion.
- Removed the repeated full identity/progress dashboard from My Forge while retaining the existing PlayerIdentityContext, update events, public profile routes and privacy boundaries.

## Player-facing visual and ownership pass

- My Forge Player Tools is a responsive visual launcher using inline Forge glyphs, short supporting copy, optional status treatment and keyboard-visible focus states. It remains separate from ordinary dashboard cards and retains a compact three-badge preview.
- Player Passport now owns the full visual completion presentation: a status summary, four distinct required milestone tiles and an image-led earned/locked badge gallery. Badge states are derived from existing profile, progression, Hero Showcase, visibility and optional transfer reads; they remain presentation-only.
- The required UI ownership model is documented in AEGIS: API identity context owns linked-player facts, Edit Passport owns profile fields, Personal Progression owns snapshots, Hero Showcase owns selected heroes, and Transfer Profile owns optional transfer planning. Repeated full identity and visibility blocks were removed from downstream surfaces.
- Edit Passport now consumes the linked player from `PlayerIdentityContext` and reads only its player profile record, avoiding a second primary `player_accounts` query. Personal Progression keeps Town Center exclusively in its linked-player context; its saved snapshot column remains historical compatibility data.
- Badge visuals use small inline SVG shield, passport, link, hero, progress, presence and transfer emblems. No remote runtime images, third-party artwork, schema change or persistence was added.

Known limitation: authenticated Supabase RLS and direct browser smoke checks require Clark's local signed-in session or a deployed preview; this session did not claim visual browser validation.
