# Release 0.7.2 — Player-facing activation

## Player Identity

- Completed the private Player Identity loading, signed-out, unlinked, linked and Supabase failure states.
- Kept `PlayerIdentityContext` as the single browser source of truth for the primary linked player.
- Consolidated linked-player reads and refreshes around the context and retained the `kingshot-player-updated` event.
- Removed the synthetic public identity route and routed both public URL forms through the real public profile projection.

## My Forge

- Added a responsive Player Headquarters with real player name, kingdom, optional alliance, verification, visibility and avatar fallback.
- Added state-driven priority actions for signing in, linking, profile completion, visibility and Hero Showcase maintenance.
- Removed the duplicate Forge Passport summary while preserving linked-player management and saved name/art functionality.

## Security and validation

- Public profile reads no longer select `user_id` and require both account and profile visibility.
- No Supabase schema change was required.
- `npm run validate:player-identity`, `npm run test:player-identity`, `npm run build` and `npm run lint` pass; lint retains existing warnings documented in `docs/AEGIS.md`.
