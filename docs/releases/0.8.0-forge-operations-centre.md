# Release 0.8.0 — Forge Operations Centre

Status: **In development**  
Branch: `release/0.8.0-operations-centre`  
Base: production merge `9bd97dcdebded96bee4ac40f8888f0bcc5724173`

## Scope and rationale

Release 0.7.5 left internal Admin destinations appended to the player sidebar.
Release 0.8.0 establishes a multi-workspace platform: Player View remains the
default, while Contributor Centre, Creator Centre, Moderation Centre and Forge
Operations Centre are available only when the signed-in account has the
corresponding capabilities.

## Architecture

`src/navigation/workspaceRegistry.ts` is the shared navigation contract. It
owns workspace labels, routes, groups, permissions and honest status labels.
`WorkspaceSwitcher` stores a preference only as a convenience; it validates
the preference against current access and cannot authorize a route. Existing
`/admin/*` implementations remain compatibility routes during migration.

## Current implementation and classifications

The Player View is separated from internal links. Operations, Contributor,
Creator and Moderation shells exist. Existing editorial, verification,
Community Art, Gift Redemption and Data Engine pages remain the source of truth
for their working slices. Sprint 8.0B adds a server-authorized User Management
foundation: safe list/detail projections, multi-role assignments, account
status, audited mutations and Player View Settings. Roles and Permissions,
the unified Audit Log and Feature Flags remain planned follow-up surfaces.
See `docs/admin/admin-feature-inventory.md`.

## Security model

Supabase RLS, server authorization, existing Forge permissions and provider
secrets remain authoritative. Workspace hiding is not security. The Player
Identity support route now uses the same explicit permission guard as adjacent
Admin routes. User Management uses forced-RLS identity tables, service-only
Auth reads, masked projections, capability checks, reasons and Owner/final-
Owner protections.

## Responsive and accessibility strategy

The switcher is keyboard-reachable, announces its menu through standard button
semantics, and remains available in the header on narrow screens. Navigation
groups use the existing drawer/backdrop/focus patterns. Release validation must
cover 390px, 768px, 1024px and 1440px, including overflow, table density,
focus visibility, status text and direct-route denial.

## Deferred features and rollout

Automatic background gift-code processing moves to Release 0.8.1 and remains
outside this release. No production merge, deployment or role mutation is part
of this local implementation without Clark's approval. Final rollout requires
the full Admin inventory, authenticated role fixtures, security checks,
production build, browser validation and a draft pull request. The current
server list is bounded to 1,000 Auth users before filtering; a database-backed
index is deferred to 8.0C.
