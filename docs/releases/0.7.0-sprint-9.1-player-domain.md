# Release 0.7.0 — Sprint 9.1 Player Domain Foundation

## Objective

Build the Player Domain on the existing Forge ownership, Hero, publishing and permission foundations without creating parallel canonical content.

## Implemented

- Canonical player identity continues to use `player_accounts` as the API-backed player record.
- Public profile presentation continues to use `player_profiles` and its existing ownership policies.
- Player Hero collection and showcase continue to reference canonical `heroes` records through `player_heroes`.
- Personal progression uses immutable `player_progression_snapshots` records.
- Each progression snapshot now has explicit public/private visibility.
- Public progression reads require both a public snapshot and a public player account/profile.
- Validation constraints cover VIP, Truegold and troop tier ranges.
- Account/date and public snapshot indexes support owner and public history queries.
- A new private progression workspace supports loading, empty, authentication, save, success and failure states.
- A new public progression route consumes only explicitly shared snapshots.
- Responsive layouts cover desktop, tablet and narrow mobile widths.

## Routes

- `/my-forge/progression` — authenticated personal progression tracking.
- `/player/:forgeId/progression` — public shared progression history.
- Existing `/my-forge/hero-collection` and `/my-forge/heroes` experiences remain the Player Hero collection and showcase surfaces.
- Existing `/player/:forgeId` remains the public player profile overview.

## Data separation

Canonical Hero facts remain published platform content. Player-owned Hero levels, showcase choices and progression snapshots reference canonical Hero records and never create editable copies of canonical Hero data.

## Database change

Migration: `player_domain_progression_visibility`

The migration adds `is_public`, validation constraints, supporting indexes and a restricted public SELECT policy to `player_progression_snapshots`.

## Validation

- Database column, indexes and RLS policy verified after migration.
- Vercel deployment and `npm run check` must pass for the exact release branch head before merge or tag.
- Product-owner validation should cover authenticated save, private snapshot privacy, public snapshot visibility, public/private profile combinations, Hero collection/showcase navigation and mobile layouts.
