# Release 0.7.3 — Forge UX Polish

## Scope

This milestone refines the existing Forge application without adding product features, domains, backend tables or schema changes. It focuses on visual consistency, responsive behaviour, accessibility and clear interaction states across shared and player-facing surfaces.

## Shared UX patterns

- Added semantic UX aliases for panel surfaces, borders, radii, control height, page gaps and mobile gutters on top of the existing Forge design tokens.
- Added a final shared polish layer for page headers, cards, controls, actions, navigation, focus rings, active states and restrained motion.
- Preserved feature-specific styling and dense Admin layouts while improving shared controls where the selectors are safe.

## Responsive and accessibility improvements

- Mobile bottom navigation now allocates space for all six existing destinations and keeps labels touch-safe at narrow widths.
- Long page titles and action groups wrap safely; mobile action groups become full-width without changing routes or hierarchy.
- Keyboard focus remains visible across links, buttons, navigation and form controls.
- Shared transitions use the existing reduced-motion token behaviour; reduced-motion users receive no disruptive movement.
- Loading, error and success panels receive consistent borders, radius and readable line-height treatment.

## Player and public surfaces

- My Forge and Player Passport retain their accepted structure and completion logic while inheriting the shared panel, control and action polish.
- Public player, progression, Hero Showcase, Gift Centre and Art Studio surfaces inherit the same typography, card treatment and responsive gutters where their existing classes allow it.
- No data ownership, privacy boundary, Supabase query or Transfer Profile requirement changed.

## Validation

Validation includes `npm run check`, TypeScript/build, lint, existing focused tests, route smoke checks and `git diff --check`. Authenticated visual browser validation remains a Clark-local step.
