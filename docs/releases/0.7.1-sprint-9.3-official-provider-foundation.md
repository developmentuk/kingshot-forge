# Release 0.7.1 — Sprint 9.3 Official Provider Foundation

## Objective

Implement the non-live, server-side infrastructure from the approved Gift
Centre Official Provider Integration Design without contacting the official
provider, introducing credentials, or adding persistence.

## Implemented

- Provider-neutral request, result, definition, and capability contracts.
- Immutable capability registry with deterministic lookup and ordering.
- Provider-neutral factory with injected registry, provider builders, and gate
  policy, plus a separate server composition root for concrete providers.
- Deterministic simulation provider that cannot return success or send a
  request.
- Isolated official-provider skeleton with no HTTP, signing, cookie, or secret
  dependency and no production-ready state.
- Exact-match product, official-provider, and approved-environment gates that
  all default off.
- Immutable internal Gift Centre domain-event contracts with scalar,
  sensitive-key-filtered metadata.
- Deterministic provider-health assessment for disabled, unknown, healthy,
  degraded, unhealthy, critical, and circuit-open states.
- Focused tests for provider selection, capability registration, dependency
  injection, simulation safety, official-skeleton isolation, gates, domain
  events, and health scoring.

## Architecture boundary

All provider modules remain under `server/giftcodes`. Pure event and health
policy remains under `shared/domains/giftcodes` and has no React, browser,
database, Player, Editorial, queue, or provider-transport dependency.

Simulation and official providers are separate modules and share only the
provider-neutral contract. Their concrete wiring lives in a server-only
composition root. Future providers can be registered with a new definition and
injected builder without changing the registry or factory implementation.

## Safety

- Live redemption remains disabled.
- The official skeleton always reports `not_supported`, `not_sent`, and
  `externalRequestSent: false`.
- The simulation provider always reports `simulation_only`, `not_sent`, and
  `externalRequestSent: false`.
- No HTTP request, request signing, credential, secret, cookie, route, queue,
  migration, persistence, Supabase write, deployment, merge, or push is part of
  this sprint.

## Validation

- `npm run check` passes, including NodeNext, structural validation, lint,

- All 27 existing and new Gift Centre tests pass.

- Executable source contains no provider endpoint or network transport

- The production client bundle contains no provider foundation, automated
