# Release 0.7.4 — Community Art Studio

## Status

Released 18 July 2026.

## Scope

Community Art Studio accepts copyable Kingshot chat art, not image files. Players submit Unicode, emoji, ASCII, box-drawing and whitespace-sensitive multiline text; the existing Art Studio gallery renders it safely and makes the exact artwork text copyable.

## Submission and moderation

- Required fields: title, description, existing Art Studio category, optional tags, artwork text, attribution, ownership confirmation and community-guideline confirmation.
- Artwork is preserved exactly as submitted. Character count uses Unicode code points; line count is derived by PostgreSQL. Limits are 20,000 characters, 100 lines and 400 characters per line.
- Lifecycle: `pending → approved → published`, or `pending → rejected`. Compatibility is separate: `untested`, `needs_testing`, `verified` or `known_issues`.
- Moderators can copy the raw text, preview it, set compatibility, edit moderation metadata, approve, reject and publish. Private notes never enter public responses.
- Forge Admin exposes the queue only to users with `moderation.manage`, with pending/approved filters, category filtering, submitter context, attribution, compatibility and visible action feedback.

## Public gallery and community interaction

- The established dark Forge Art Studio gallery remains the public foundation: search, sorting, categories, favourites, metadata, size classification, compatibility labels, preview and Copy Art.
- Public reads are published-only and return safe text-art fields without user IDs, private notes or moderation identity.
- Copy Art writes `artwork_text` only to the clipboard; titles, descriptions and metadata are never included. Newlines, repeated spaces, Unicode and emoji are preserved.
- Browser rendering is escaped `<pre>` text. Submitted content is never interpreted as HTML, Markdown or executable markup. Kingshot rendering may differ by device.
- Published community submissions show creator attribution as profile display name, an explicitly supplied creator name or `Anonymous`.
- Signed-in players can add one positive reaction per published artwork and may change or remove it. Public totals never expose the reacting users.

## Persistence changes

`community_art_text_correction` safely converted the empty image-oriented table to text art, removed image constraints and storage policies, added generated counts and compatibility fields, rebuilt the public projection, and tightened grants. The dedicated `community-art-submissions` bucket was verified empty and unreferenced; it remains private and unused because Supabase protects bucket deletion from direct SQL.

`community_art_reactions` adds the smallest separate reaction boundary. Its row-level policies restrict ownership and published artwork, while `community_art_reaction_security` makes the public aggregate view security-invoker and pins the trigger search path.

Legacy `submissions`, `favourites`, `companion-images` and unrelated policies were not changed. No supplied example artwork was imported or automatically published.

## Validation

Focused text-preservation, clipboard-boundary, ownership, moderation, attribution, reaction and public-filter tests passed alongside `npm run check`, TypeScript, lint, production build, `git diff --check`, Supabase policy checks and advisors.
