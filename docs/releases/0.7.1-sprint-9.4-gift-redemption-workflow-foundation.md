# Release 0.7.1 — Sprint 9.4 Gift Redemption Workflow Foundation

## Objective

Implement the disabled local workflow and persistence proposal needed before
any Gift Centre auto-redemption can be approved.

## Implemented

- Stable result codes with separate UI-safe wording.
- Explicit request and finalize-once attempt lifecycles.
- Purpose-, user-, character-, provider-, mode-, environment-, version-, and
  digest-bound consent.
- Injected Player, publication, consent, provider, rate-limit, and hold ports.
- Canonical length-prefixed v2 idempotency with SHA-256 and duplicate handling.
- Disabled queue policy with bounded claims, leases, optimistic versions,
  mutable rechecks, backpressure, and stale-worker recovery.
- Three-attempt retry at 30/120-second bases, deterministic injected jitter,
  no transport retry, and explicit ambiguity lock.
- Safe projections, non-executable API descriptors, strict body parsing, and
  support capability boundaries.
- Expanded immutable audit events.
- An unapplied seven-table migration proposal with RLS, explicit grants,
  constraints, queue indexes, immutable-history guards, and safe views.

## Safety

- Product, Official Provider, approved-environment, and queue gates default off.
- Simulation cannot report success or send a request.
- The Official Provider reports `not_supported`, `not_sent`, and
  `externalRequestSent: false`.
- No endpoint, transport, signer, credential, cookie, executable route, worker
  schedule, migration apply, Supabase write, deployment, merge, or push exists.

## Database state

The connected project was inspected read-only. The migration remains local and
unapplied and seeds no enabled state. No canonical Gift Code publication table
or view is deployed, so the proposal stores an immutable publication contract
without duplicating Editorial content.

## Validation

- `npm run check` passes NodeNext, structural validation, lint, TypeScript, and
  the Vite production build. Lint retains seven pre-existing React warnings in
  Player/Auth/Role contexts and `useDataset`; no Sprint 9.4 file is involved.
- The server TypeScript configuration passes independently.
- All 51 local Gift Code tests pass, including the Sprint 9.3 provider suite and
  Sprint 9.4 workflow, consent, eligibility, idempotency, queue, retry,
  ambiguity, projection, API, capability, and audit coverage.
- The unapplied SQL passes the PostgreSQL 17 parser and structural assertions
  for RLS, grants, safe views, append-only history, idempotency, and disabled
  defaults.
- Source and production-bundle scans find no Gift Code transport, endpoint,
  signing value, credential field, cookie field, executable route, or client
  import of server-only Gift Code modules.
- `npm audit` reports 10 existing development/toolchain advisories: 6 high and
  4 moderate, with none critical. No automatic fix or dependency change was
  attempted.

## Review gates

Clark and Aegis must approve the schema before application. Player and
Editorial owners must approve their projection contracts. Privacy, Security,
Legal, database, and operations approval remains required before persistence,
queue activation, or provider communication.
