# Release 0.8.0 workspace visual audit

Sprint 8.0C audit of the shared workspace shell. The audit focuses on reusable components and records the secure recruitment workflow as a separate implementation gap.

| Defect | Affected component | Underlying cause | Fix | Responsive impact | Accessibility impact | Status |
| --- | --- | --- | --- | --- | --- | --- |
| White cards clash with the dark shell | Workspace overview cards | Legacy light-surface rules in `App.css` | Dark charcoal surfaces, neutral/violet borders and readable secondary text | Cards retain a one-column mobile fallback | Contrast and focus states are explicit | Fixed in shared CSS |
| Switcher was oversized and low contrast | `WorkspaceSwitcher`, header | Light menu/button styling and long descriptions | Compact dark trigger, aligned menu, selected/hover/focus states | Menu becomes a viewport sheet below 760px | Keyboard focus and selected state remain visible | Fixed in shared CSS |
| Hero headings and page spacing were too large | Workspace home/status pages | Generic display scale was reused for operational pages | Compact heading scale and reduced page padding | More useful content remains above the fold | Heading hierarchy is easier to scan | Fixed in shared CSS |
| Sidebar statuses wrapped into labels | `AppLayout` navigation links | Status text was not separated or constrained | Separate non-wrapping status element; planned/unavailable items are non-links | Sidebar remains usable in the mobile drawer | Planned destinations no longer expose dead navigation | Fixed in shared component |
| Overview pages repeated navigation | Contributor, Creator and Moderation homes | Generic destination-card template was used as the dashboard | Contributor catalogue and honest foundation copy added; deeper stateful dashboards remain deferred | Public catalogue is responsive | Status is conveyed by text, not colour alone | Partially addressed; stateful dashboard deferred |
| Recruitment application path absent | Public and Operations recruitment surfaces | No application domain, persistence, API or RLS contract exists on branch | Public catalogue explicitly states workflow is in development | No incomplete form is presented | No personal data is collected by the catalogue | Open blocker |

## Validation notes

The shared CSS and component changes are validated by the TypeScript/build checks. Exact rendered checks at 390px, 768px, 1024px and 1440px require a running preview and browser-capable session; this worktree does not provide evidence of authenticated visual validation yet.

No white workspace-card legacy rule should remain active for the workspace surfaces. The public contributor pages intentionally use the same dark surface language.
